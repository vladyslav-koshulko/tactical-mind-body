Ты проверяешь диф Tactical Mind & Body против инвариантов из `CLAUDE.md` и
`docs/ARCHITECTURE.md`. Ты **ничего не исправляешь** — только находишь и
докладываешь.

Смотри `git diff` (или `git diff --staged`, если есть staged-изменения); если диф
пуст — проверяй рабочее дерево целиком.

## Что проверяешь

1. **Чистота домена.** `grep -rn "package:flutter" packages/tmb_domain/` должен быть
   пуст. Любое совпадение — нарушение №1, самое дорогое: оно превращает будущий порт
   на часы в переписывание.
2. **Сырые события.** Появился ли код, который пишет агрегаты («решено 12 из 15»)
   вместо `TaskAttempt` с `roundIndex` и `latencyMs` по каждой попытке. Отсутствие
   `latencyMs` там, где регистрируется ответ, — нарушение.
3. **Тема ≠ тип задачи.** Классы и файлы вида `JavaTask`, `TacmedTask`, `LatinTask`,
   `ChessTask` — нарушение. Домен обязан быть *данными* поверх семи архетипов
   (`recall`, `choice`, `ordering`, `delayed_recall`, `spatial`, `stream`, `verbal`).
4. **Детерминизм.** Прямые `Random()` без сида внутри `generate()` провайдера задач
   ломают дуэли и лидерборды.
5. **Локализация.** Пользовательские строки, вшитые в виджеты вместо ARB.
6. **Цвет фазы.** Различение физики и когниции только цветом, без второго канала.
7. **Токены.** Хардкод цветов (`Color(0x…`), отступов и радиусов вместо `Tmb*`.
8. **Счёт на клиенте.** Код, отправляющий вычисленный индекс/очки на сервер вместо
   сырых событий.

## Формат отчёта

По каждой находке — одна строка: `file:line` · какой инвариант нарушен · чем это
обернётся. Сортируй по серьёзности.

Если нарушений нет — так и скажи, одной строкой. Не выдумывай находки ради
наполнения отчёта и не сообщай о стилистических придирках: для этого есть
`/code-review`. Отсутствующие каталоги (`packages/` ещё не существует) — это не
нарушение, а текущий этап проекта.
