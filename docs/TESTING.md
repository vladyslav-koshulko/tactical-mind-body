# Тестирование и проверка приложения

Как проверить, что приложение работает и выглядит как задумано, не отправляя его
на чужие телефоны. Четыре слоя: от дешёвого к дорогому. Облачный CI
(`.github/workflows/flutter.yml`) закрывает слои 1–2; слои 3–4 живут **локально** —
это сознательное решение: у GitHub нет эмулятора с нужным образом за разумное время.

| Слой | Что ловит | Где идёт | Команда |
|---|---|---|---|
| 1. Unit и виджет-тесты | логика, структура экранов, локализация | CI + локально | `flutter test` в пакете |
| 2. Скриншот-тесты (golden) | поехавшая вёрстка, шрифты, переполнения | только локально | `scripts/golden.sh` |
| 3. Сквозной тест на эмуляторе | настоящая БД, assets, роутер, плагины | только локально | `scripts/emu.sh test` |
| 4. Глаза владельца на эмуляторе | всё остальное: ощущение, ритм, читаемость | только локально | `scripts/emu.sh install` |

## Локальный CI — `scripts/ci-local.sh`

Единая точка входа. **Запускать перед каждым push.** Делает то же, что GitHub, плюс
слои 2–4, и в конце оставляет на эмуляторе сборку, которая прошла проверку:

1. `pub get`, `format`, `analyze --fatal-infos`;
2. тесты `tmb_domain`, `tmb_data`, `tmb_ui`, `apps/mobile`;
3. скриншот-тесты (golden);
4. валидатор встроенных паков;
5. сборка debug-APK;
6. эмулятор: загрузка → стереть данные → сквозной тест со скриншотами каждого шага;
7. установка **той же сборки** поверх, запуск с чистого состояния.

```bash
scripts/ci-local.sh            # всё
scripts/ci-local.sh --no-emu   # без эмулятора, быстро (пока правите вёрстку или логику)
scripts/ci-local.sh --keep-data  # не стирать данные приложения в конце
```

Результат: `build/local-ci/report.md` (таблица этапов), `build/local-ci/screenshots/`
(скриншоты шагов теста + `99_final_state.png`), `build/local-ci/last-verified.txt`
(коммит, время, итог). Код возврата ненулевой, если что-то упало.

> Прогон без эмулятора помечается в отчёте как «зелёное, но без эмулятора» — это не
> то же самое, что «проверено».

## Эмулятор — `scripts/emu.sh`

AVD **tmb_pixel**: Pixel 5, Android 35 (Google APIs, x86_64), 2 ГБ ОЗУ, окно видно на
рабочем столе. Нужен доступ к `/dev/kvm` (пользователь в группе `kvm`).

```bash
scripts/emu.sh start      # поднять и дождаться загрузки (~20 с, с quickboot быстрее)
scripts/emu.sh install    # собрать, поставить поверх, запустить
scripts/emu.sh test       # сквозные тесты (integration_test/app_flow_test.dart, 3 сценария, ~1.5 мин)
scripts/emu.sh shot имя   # скриншот экрана → build/local-ci/screenshots/имя.png
scripts/emu.sh reset      # стереть данные приложения
scripts/emu.sh status     # что запущено, что установлено, когда последний раз проверяли
scripts/emu.sh stop
```

### Правило «на эмуляторе всегда свежее»

После любой серии изменений, которую владелец должен увидеть, на эмуляторе стоит
**последняя проверенная сборка**: после `ci-local.sh` это так автоматически. Если
правка маленькая и полный прогон избыточен — `scripts/emu.sh install`, но тогда в
отчёте честно сказано, что полный прогон не делался.

## Скриншот-тесты — `scripts/golden.sh`

`apps/mobile/test/golden/screens_golden_test.dart` рисует экраны (дашборд, старт
сессии, настройки, категории, украинская локаль, узкий экран 320 px с текстом ×1.5)
в `test/golden/goldens/*.png`. Шрифты Oswald, JetBrains Mono и иконки Material
грузятся в тесте явно — без этого `flutter test` рисует текст заглушкой Ahem.

- Сверка: `scripts/golden.sh`. Падение показывает diff в `test/failures/`.
- После **осознанной** правки вёрстки: `scripts/golden.sh --update`, затем смотрим
  PNG глазами и коммитим вместе с кодом. Обновлять эталоны вслепую нельзя — тогда
  тест ничего не проверяет.
- Эталоны зависят от платформы рендера, поэтому в GitHub CI исключены
  (`--exclude-tags golden`, тег объявлен в `apps/mobile/dart_test.yaml`).

## Сквозные тесты — `integration_test/app_flow_test.dart`

Три сценария идут по порядку в одном процессе и делят БД на устройстве (настоящая БД,
настоящие паки, настоящий роутер). Скриншоты каждого шага пишет драйвер
(`test_driver/integration_test.dart`) в `build/local-ci/screenshots/`.

1. **Дым:** дашборд → «Начать операцию» → физика → подход → «Эвакуация» с подтверждением →
   итоги «Прервана» → дашборд (`01_…`–`06_…`).
2. **Полная короткая сессия офлайн** (критерий v0.1, `10_…`–`24_…`): дашборд помнит «Прервана»
   → **экран настроек** (шаговые кнопки: кругов 5 → 2; диалог ввода значения: окно 180 → 30 с;
   прокрутка до нижних панелей) → старт → круг 1 из 2 → подходы → когнитивное окно →
   **уход приложения в фон** (см. ниже) и заглушка паузы → ответ на задачу → удержание окна до
   срока (D15, остаток ~25 с — реальное ожидание, поэтому окно 30 с) → круг 2 из 2 с оценкой
   круга 1 → оценка круга 2 → итоги «Завершена» → дашборд: «Завершена», «Кругов: 2».
   Задачи отвечаются любым допустимым способом (`_answerTasks`: число, текст, запоминание,
   verbal с самопроверкой) — верность ответа не проверяется, проверяется что сессия идёт дальше.
   Длительности сокращены **настоящими настройками приложения**, а не подменой провайдеров.
3. **Украинская локаль** (`30_…`–`37_…`): `TmbApp(locale: uk)` — дашборд, настройки, физика,
   когнитивная фаза, диалог эвакуации, итоги.

### Настоящий уход в фон

`flutter drive` на Android не даёт хосту реагировать на шаги теста, поэтому
`scripts/emu.sh test` поднимает следящий процесс (`cmd_lifecycle_watch`): тест печатает маркер
`TMB_E2E_BACKGROUND` в `debugPrint` (logcat, тег `flutter`), хост по маркеру жмёт
`KEYCODE_HOME`, снимает лаунчер (`17a_launcher_while_backgrounded.png`) и возвращает
приложение через `monkey`. Тест ждёт заглушку паузы («Таймер остановлен»), проверяет, что условие
задачи скрыто, жмёт «Продолжить» и убеждается, что задача вернулась. Флаг
`--dart-define=TMB_REAL_LIFECYCLE=true` ставит `emu.sh`; при запуске `flutter drive` вручную без
него тест имитирует `hidden`/`resumed` через binding (тот же код приложения, но без настоящей ОС).

Скриншоты: `shot()` ждёт три кадра перед снимком — иначе снимок поверхности иногда ловит
переходный экран («Подготовка операции», спиннер итогов).

Новый пользовательский сценарий v0.x — новый шаг в этих тестах.

## Web-сборка (только для разработки)

`apps/mobile/web/` нужен, чтобы быстро посмотреть UI во встроенном браузере Claude
Code (`.claude/launch.json` → `flutter-web`, статика из `apps/mobile/build/web`;
перед запуском: `cd apps/mobile && flutter build web --debug`). Drift работает через
`sqlite3.wasm` + `drift_worker.js` (лежат в `web/`, версии привязаны к `pubspec.lock`:
sqlite3 3.9.1, drift 2.35.4 — при обновлении пакетов обновить и файлы).

Web — **не** целевая платформа: вибро, wakelock и «Поделиться» там не проверяются, а
поведение чисел отличается (в JS целые — это double). Слово «работает в вебе» ничего
не говорит о телефоне; решающий слой — эмулятор.

## Что ещё не покрыто

- Реальное железо: вибро, блокировка экрана и мультизадачность на настоящем телефоне,
  шеринг файла. Эмулятор проверяет сворачивание по HOME, но не гашение экрана кнопкой питания.
- Другие размеры экрана и ориентация (можно добавить второй AVD).
- Украинская локаль: UI проверен, но **контент задач и упражнений только `ru`**
  (`assets/content/ru`) — в украинском интерфейсе задачи и часть названий остаются русскими.
  Приложение жёстко берёт `ru` по умолчанию и не следует системной локали (переключателя нет):
  `uk` включается только параметром `TmbApp(locale:)`.
- Остальные архетипы в сквозном прогоне: во встроенных паках только recall, delayed_recall и
  verbal; choice/ordering/spatial покрыты только виджет-тестами.
- Нативный выбор файла/экспорт.
- Ответы на задачи не проверяются на верность (в сквозном тесте нужен лишь принятый ответ).

## Установка окружения с нуля

Всё лежит в домашнем каталоге, `sudo` не нужен.

```bash
# JDK 17 (Temurin) → ~/development/jdk-17
# Android SDK command-line tools → ~/Android/Sdk/cmdline-tools/latest
source scripts/env.sh
yes | sdkmanager --licenses
sdkmanager --install "platform-tools" "emulator" "platforms;android-36" \
  "build-tools;36.0.0" "ndk;28.2.13676358" \
  "system-images;android-35;google_apis;x86_64"
flutter config --android-sdk ~/Android/Sdk --jdk-dir ~/development/jdk-17
scripts/emu.sh create
```

Версия NDK — та, что просит Flutter (`ndkVersion` в `FlutterExtension.kt`); при
обновлении Flutter её нужно сверить, она же прописана в `flutter-apk.yml`.
