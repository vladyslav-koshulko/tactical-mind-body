# Расширяемость — контракты, которые надо заложить сразу

Документ отвечает на вопрос: как покрыть произвольные когнитивные домены (Java, Rust,
кибербез, тактика, такмед, латынь, диагностика, шахматы, языки…), кастомизацию,
виджеты и интеграции — **не переписывая ядро на каждую новую тему**.

Дополняет [ARCHITECTURE.md](ARCHITECTURE.md). Всё, что здесь помечено «в v0.1», стоит
почти ноль сейчас и почти нереализуемо потом.

---

## 1. Главная мысль: тема — не тип задачи

Соблазн — завести типы `JavaTask`, `TacmedTask`, `LatinTask`. Это тупик: каждая новая
тема становится изменением кода, релизом и ревью в Play.

На деле **механик мало, а тем бесконечно много**. «Вопрос по дженерикам Java», «доза
адреналина при анафилаксии» и «перевод латинского термина» — это одна и та же механика
*«вспомни ответ»* с разным содержимым.

### Семь архетипов — исчерпывающий список механик

| Архетип | Механика | Примеры содержимого | Машинно проверяем |
|---|---|---|---|
| `recall` | Ввести ответ | Арифметика, латинский термин, синтаксис Rust | ✅ |
| `choice` | Выбрать из N | Тест по МГП, диагноз по симптомам, класс уязвимости | ✅ |
| `ordering` | Упорядочить шаги | Протокол MARCH, порядок выполнения кода, этапы развёртывания | ✅ |
| `delayed_recall` | Запомнить сейчас — ответить через круг | Координаты, отрывок книги, позиция на доске | ✅ |
| `spatial` | Работа с сеткой/картой | Сектора на карте, шахматная задача, схема помещения | ✅ |
| `stream` | Поток стимулов на скорость | n-back, Струп, go/no-go | ✅ |
| `verbal` | Произнести вслух, самооценка | «20 терминов без повтора», скороговорки | ❌ |

**Все запрошенные домены раскладываются на эти семь.** Это и есть доказательство, что
абстракция взята правильно: если бы что-то не легло — абстракция была бы неверной.

> ⚠️ `verbal` не проверяется машиной, поэтому **не может влиять на Индекс Оперативника
> и лидерборды** — иначе рейтинг ломается о самооценку. Признак проверяемости входит в
> контракт, а не додумывается потом.

## 2. Контракт провайдера задач — **в v0.1**

```dart
abstract interface class CognitiveTaskProvider {
  String get id;                    // 'math.arithmetic', 'java.generics'
  TaskArchetype get archetype;
  Set<String> get domains;          // 'it.java', 'med.latin', 'mil.tacmed'
  DifficultyBand get band;          // recruit … spetsnaz
  Set<Locale> get locales;
  bool get isMachineVerifiable;
  Duration get estimatedTime;

  /// ДЕТЕРМИНИРОВАННО: одинаковый seed -> одинаковая задача.
  CognitiveTask generate(TaskSeed seed);

  TaskVerdict verify(CognitiveTask task, TaskAnswer answer);
}
```

Ядро **не знает** о Java, латыни и такмеде. Оно знает только этот интерфейс. Новый
домен = новый пак данных или новый провайдер, а не правка движка.

### Почему `generate(seed)` детерминирован

Без сида невозможны: дуэли с другом на одинаковых задачах, честное сравнение в
лидерборде, воспроизведение спорной сессии при разборе бага, и офлайн-детерминизм при
синхронизации. Ввести сид в v0.1 — одна строка. Ввести позже — переделка всех
провайдеров и потеря сопоставимости со старой историей.

## 3. Сессия как список блоков — **в v0.1**

Сейчас движок мыслит «круг → пауза». Это закрывает половину запросов пользователя.

```dart
sealed class SessionBlock {}
class PhysicalBlock  extends SessionBlock { ... }
class CognitiveBlock extends SessionBlock { ... }
class RestBlock      extends SessionBlock { ... }

class SessionTemplate {
  final List<SessionBlock> blocks;   // произвольная последовательность
}
```

Тогда всё это — просто шаблоны, а не режимы в коде:

- **Dual-Task классический** — чередование (текущее поведение)
- **Только физика** — программы тренировок без когнитивных пауз
- **Только когниция** — «тренировка в транспорте», без физнагрузки
- **Кастом** — пользователь сам собирает последовательность

Стоимость сейчас — правильная форма данных. Стоимость потом — переписывание движка
сессии, аналитики и синхронизации.

## 4. Контентные паки — формат вместо кода

> Канонический формат обмена — **JSON** с `schemaVersion` (решение D3 в
> [ARCHITECTURE §10](ARCHITECTURE.md#10-решения-от-2026-11-19-категории-свой-контент-прогрессия)).
> YAML ниже — только для читаемости. Рабочий образец — [`uncertainty.pack.json`](../assets/content/ru/uncertainty.pack.json).

```yaml
pack: mil.tacmed.ru
title: Тактическая медицина — база
locale: ru
domain: mil.tacmed
license: CC-BY-4.0
levels: [recruit, operator]
items:
  - archetype: ordering
    prompt: Восстановите порядок протокола MARCH
    items: [Massive hemorrhage, Airway, Respiration, Circulation, Hypothermia]
    difficulty: 0.35
  - archetype: choice
    prompt: Максимальное время наложения турникета до переоценки
    options: ['30 мин', '2 часа', '6 часов', 'Без ограничений']
    answer: 1
    difficulty: 0.5
```

Паки грузятся через Remote Config + бандл в ассетах (см. ARCHITECTURE §6), то есть
**новые темы выходят без релиза в Play**.

### Импорт чужих форматов — самый большой рычаг

Один человек не напишет десятки профессиональных доменов. Но их **уже написали**:

- **Anki (`.apkg`)** — гигантские готовые колоды по медицине, латыни, языкам, праву
- **CSV / Markdown** — простейший путь для自 своего контента
- **LLM-генерация** с обязательной ручной вычиткой перед публикацией

Импортёр Anki→pack — это несколько дней работы, которые дают доступ к контенту,
который иначе писался бы годами. Врач из примера получает латынь и симптоматику в
первый же день.

## 5. Профиль вместо «возраста»

Пул задач собирается из тегов, а не из демографии:

```
domains:  [it.java, it.rust, sec.appsec]
level:    operator
locales:  [ru, en]
exclude:  [verbal]        # «не могу говорить вслух в зале»
```

> ⚠️ **Не собирать точный возраст.** Как только в приложении появляются пользователи
> младше 13, включается Families-политика Google Play и жёсткие ограничения на рекламу
> и сбор данных. Ставим возрастной порог 16+ и спрашиваем **уровень подготовки**, а не
> дату рождения. Уровень полезнее для подбора задач и не создаёт регуляторного риска.

## 6. Интеграция со сторонними приложениями — двумя шагами

Запрос: другое приложение (шахматы, книги) временно встраивается в когнитивную паузу,
возможно на рекламной основе.

### Честная оценка рисков прямого запуска чужого приложения

- Выход из приложения на 3-минутной паузе — **потеря контроля над таймером**. Часть
  пользователей не вернётся, сессия не закроется, событий для аналитики не будет.
- Проверить результат можно только если партнёр **специально** реализует ответный
  вызов. Универсального способа нет ни на Android, ни на iOS.
- Контент внутри тренировочной петли контролирует третья сторона — это репутационный и
  политический риск.
- Оплаченная выдача чужого контента под видом тренировки — **нативная реклама**, её
  обязательно маркировать, иначе это вводит в заблуждение по политике Play.

### Рекомендация: сначала паки, потом рантайм

**Шаг A — партнёрский контент-пак (дёшево, безопасно, ~90 % ценности).**
Шахматное приложение отдаёт **контент** (позиция FEN + лучший ход), книжное — отрывки
для `delayed_recall`. Всё крутится **внутри нашего приложения**: наш таймер, наш скоринг,
наш UI, брендированная плашка «Пак от партнёра». Никакого выхода из сессии.

**Шаг B — передача наружу, только с реальным партнёром.** Документированный контракт
`tmb-task://` с подписанным ответным колбэком. Делать не раньше, чем появится
подтверждённый спрос от партнёра, — иначе это спекулятивная сложность.

## 7. Виджеты — **подготовить хранилище в v0.1**

Виджет живёт вне Flutter-движка и читает не нашу БД, а общее хранилище
(`SharedPreferences` / App Group). Поэтому в v0.1 после каждой сессии пишем короткую
сводку в этот общий стор: серия, последний Индекс, Стойкость, дата.

Заложить сейчас — одна функция. Потом — распутывание слоя данных.

**Интерактивный виджет — сильная фича, а не украшение:** одна микро-задача прямо с
рабочего стола («когнитивный перекус»). Android 12+ и iOS 17+ это умеют. Для приложения
про регулярность это лучший инструмент удержания из существующих.

## 8. Кастомизация интерфейса — пресеты, а не палитра

Свободный выбор цветов **сломает главный сигнал системы**: зелёный = физическая фаза,
оранжевый = когнитивная. Если пользователь перекрасит обе фазы в синий, продукт
потеряет то, что делает его продуктом.

**Решение:** темы как *режимы переменных* (в Figma коллекция уже с именованным режимом —
добавить второй дёшево), а не как произвольные цвета:

- `Тактический зелёный` (по умолчанию) · `Ночной янтарь` · `Арктика` · `Пустыня`
- `Дневной` — повышенный контраст для яркого солнца
- Размер шрифта, отключение анимаций, сила вибрации

Инвариант темы: **пара фаз обязана оставаться различимой**. Проверяется тестом, а не
на глаз.

> ⚠️ **Находка по доступности.** Зелёный и оранжевый — одна из худших пар при
> дейтеранопии и протанопии. У нашей конкретной пары спасает разница яркости
> (`#A6FF4D` заметно светлее `#FF8A1F`), но **опираться только на тон нельзя**. Фазу
> обязан дублировать второй канал: форма индикатора, звук, тактильный отклик и
> подпись. Это и без дальтонизма правильно — фазу должно быть видно боковым зрением,
> когда читать надписи тяжело.

## 9. Ловушка: кривая деградации требует сопоставимости

Кривая деградации сравнивает точность на 1-м и 5-м круге. Если на 5-м круге задачи
оказались **объективно сложнее**, кривая измерит не усталость, а подбор задач.

Поэтому в контракте есть `difficulty`, и правило: **внутри одной сессии сложность
держится примерно постоянной**, а разброс нормализуется по рейтингу задачи. Иначе
главная метрика продукта врёт — тихо и убедительно.

Когда наберётся статистика, рейтинг сложности пересчитывается по фактическим ответам
(доля верных и медианное время), а не по оценке автора пака.

## 10. Что ещё стоит заложить

| Идея | Почему сильно |
|---|---|
| **Интервальное повторение между сессиями** | Механика «запомни → вспомни позже» уже есть. Расширить её до SM-2 — и приложение начинает **реально учить профессии**, а не развлекать. Врач учит латынь, разработчик — Rust, военный — термины. Это превращает фитнес-гаджет в инструмент обучения и радикально усиливает подписку. |
| **Аудио-задачи** | Для бега и улицы, где в экран не смотрят. Прямо стыкуется с премиум-фичей «Голос Командира». |
| **Валидированные тесты** (n-back, Струп, go/no-go) | Делают аналитику защитимой: это признанные инструменты, а не самодельные метрики. |
| **Дуэль с другом** | Одинаковый сид → одинаковые задачи → честное сравнение. Возможно только если сид заложен в v0.1. |
| **Адаптивная сложность** | Кривая деградации даёт сигнал, которого нет ни у кого. Автоподстройка нагрузки — естественное продолжение. |

## 11. Итог: что делаем в v0.1, а что откладываем

### Заложить сразу — дёшево сейчас, неподъёмно потом

1. `CognitiveTaskProvider` + семь архетипов вместо тем
2. Сессия как список блоков (открывает «только физика» / «только когниция» / кастом)
3. **Детерминированная генерация по сиду**
4. Схема тегов задач: домен, уровень, локаль, сложность, проверяемость
5. Декларативный формат пака (даже если v0.1 везёт только встроенные)
6. Тема как режим токенов + дублирование фазы нецветовым каналом
7. Запись сводки сессии в общее хранилище под будущий виджет

### Отложить осознанно

| Что | Когда | Почему не сейчас |
|---|---|---|
| Импорт Anki/CSV | v0.2 | Нужен после того, как формат пака устоится |
| Виджет | v0.3 | Хранилище готово, поверхность делается быстро |
| Темы-пресеты | v0.3 | Токены готовы, вопрос только в наборе |
| Интервальное повторение | v0.7 | Отдельный крупный продукт внутри продукта |
| Партнёрские паки | v0.7 | Нужен вес аудитории для переговоров |
| Рантайм-интеграция `tmb-task://` | не раньше v1.x | Только под конкретного подтверждённого партнёра |
| UGC-паки от сообщества | не раньше v1.x | Модерация — отдельный продукт. Плюс OPSEC в военных темах и запрет на медицинские советы. |

## 12. Регуляторные ограничения по доменам

- **Медицина.** Диагнозы и симптоматика — только как учебный материал. Обязательный
  дисклеймер, никаких формулировок, похожих на медицинскую рекомендацию.
- **Военные темы.** Учебный контент по тактике и терминологии в Play проходит, но
  огневая подготовка влияет на возрастной рейтинг. Никаких инструкций по изготовлению
  оружия и взрывчатки. При UGC — отдельная политика OPSEC: пользователи не должны
  публиковать непубличные ТТХ, позывные, реальные позиции.
- **Кибербезопасность.** Теория, классы уязвимостей и защита — да. Рабочие эксплойты и
  инструкции по атаке — нет.
