а не только вычислять.

**Разбивка:**

## R5. Рост нагрузки

**Что хотим.** По истории: сколько дней прошло, что и сколько раз делалось. Мышцы
успели восстановиться → чуть больше повторений; давно не тренировался → мягче, причём
снижение можно приложить к началу, середине или концу круга.

**Что нужно от данных (Фаза 1 / v0.1):** запись `ExerciseSet` на каждое упражнение —
`prescribed` и `done` — плюс единица (`reps` / `seconds`, чтобы планка считалась
секундами). Дополнительно — необязательная оценка «тяжело/нормально/легко» одним
нажатием (`rpe`, поле уже есть в модели).

**Стартовые правила** — параметры, а не истина; калибруются на реальной истории:

| Условие по упражнению | Решение |
|---|---|
| Прошло < 48 ч | Без повышения |
| 2–7 дней, прошлый раз выполнено всё | +1 (база ≤ 10) или +2 (база > 10) |
| 2–7 дней, выполнено не всё | Без изменений |
| 8–14 дней | Без изменений |
| > 14 дней | −10…20 % (> 30 дней — больше), округление вверх |
| Прошлый раз «тяжело» (`rpe`) | Повышение не применяется |

Форма снижения по кругам — параметр `shape`: `even` / `front` / `middle` / `back`.

**Ограничения (D6):** план фиксируется на старте сессии и не меняется реактивно внутри
неё; всегда объясняется одной строкой; отключается; правится вручную. Потолок прироста
за сессию — обязателен. Это не медицинская рекомендация, формулировки в приложении —
без «безопасно» и «оптимально».

**Разбивка:**
- [ ] `ExerciseSet`, `unit`, `rpe` в схеме и логах — **v0.1**
- [ ] Per-exercise цели вместо глобального «N повторений на всё» — v0.1 (меняет модель
      настроек: сейчас `fixedReps` одно на все упражнения)
- [ ] `nextPrescription()` + юнит-тесты на таблицу выше — v0.2
- [ ] Показ «почему +2» на брифинге, переключатель — v0.2
- [ ] Прогрессия в аналитике: график нагрузки по упражнению — v0.3

## R6. Экспорт и импорт

**Что хотим.** Набрать большой список упражнений (например, в ИИ-чате) и импортировать
к уже существующим.

**Формат (D3):** JSON, `schemaVersion: 1`, два вида документов — набор упражнений и пак
задач. Тот же конвейер примет CSV и Anki (v0.2 в роадмапе).

**Поток импорта (D5):** файл или вставка текста → валидатор → предпросмотр (новых,
дублей, ошибок со строками) → подтверждение → пак с пометкой «импортировано».

**Ключевая фича для сценария «из ИИ-чата»:** в приложении лежит готовый **промпт-шаблон**
с формой JSON и примером — кнопка «скопировать». Без него ИИ выдаёт невалидный формат,
и импорт упирается в ошибки.

**Разбивка:**
- [ ] Схема JSON упражнений (`id`, `name`, `unit`, `muscleGroups`, `inventory`) — **Фаза 1**
- [ ] Валидатор паков и упражнений в `tmb_domain` (нужен и для встроенных паков) — v0.1
- [ ] Экспорт одной кнопкой (весь пользовательский контент) — v0.1, дёшево: сериализация
- [ ] Экран импорта с предпросмотром, промпт-шаблон — v0.2
- [ ] Импорт CSV; Anki `.apkg` — v0.2
- [ ] Вычитка контента ИИ — всегда ручная; импорт показывает метку «не проверено»

### Что считаю спорным (решение за владельцем)

1. **Формат — JSON, не YAML** (D3). Все прежние примеры в доках на YAML; я оставил их
   для читаемости, но канон — JSON.
2. **Свой контент не влияет на Индекс** (D4). Иначе читерство тривиально. Цена: человек,
   который пишет свои задачи, не получает за них очков в рейтинге.
3. **Прогрессия включена по умолчанию** или опциональна. Рекомендую: включена, с видимой
   строкой «почему» и выключателем.
